Sequence Diagram (دیاگرام توالی تراکنش‌ها و رویدادها)

دیاگرام توالی زمانی (Sequence Diagram) سناریوی کلیدی سامانه: ارسال درخواست بارگذاری فرم توسط کلاینت، تعامل با کش لوکال استوریج، اعتبارسنجی قوانین شرطی، ارسال تراکنشی به دیتابیس پستگرس از طریق RPC، ثبت CDC و انتشار بلادرنگ پاسخ جدید به داشبورد ادمین از طریق کانال وب‌سوکت.

sequenceDiagram
 autonumber
 actor User as پاسخ‌دهنده (Respondent)
 participant Client as موتور فرم‌ساز (React Client)
 participant Storage as کش مرورگر (LocalStorage)
 participant Edge as لبه CDN (Vercel)
 participant SupaAPI as API سوپابیس (PostgREST)
 participant Postgres as هسته دیتابیس (PostgreSQL)
 participant Realtime as سرور ریل‌تایم (Phoenix WS)
 actor Admin as داشبورد ادمین (Admin Portal)

 %% Session Start
 User->>Client: ورود به لینک /f/:slug
 Client->>Storage: بررسی وجود پیش‌نویس موضعی (Check Draft)
 Storage-->>Client: بازیابی پاسخ‌های ذخیره‌شده (یا شیء خالی)
 Client->>Edge: GET /forms?slug=eq.:slug&published=eq.true
 Edge->>SupaAPI: بررسی دسترسی RLS عمومی (anon)
 SupaAPI->>Postgres: SELECT * FROM forms WHERE slug = :slug
 Postgres-->>SupaAPI: متادیتای فرم + لیست سوالات و رول‌ها
 SupaAPI-->>Edge: پاسخ JSON فرم
 Edge-->>Client: تحویل فرم با سوالات به کلاینت

 %% Question Answering
 User->>Client: وارد کردن پاسخ سوال و زدن دکمه تایید / Enter
 Client->>Client: ولیدیشن محلی (Regex موبایل / اجباری بودن)
 Client->>Storage: ذخیره آنی جواب در LocalStorage (Auto-Save)
 Client->>Client: ارزیابی Logic Rules (آیا شرط پرش برقرار است؟)

 %% Submission
 User->>Client: تکمیل آخرین سوال و ارسال نهایی فرم
 Client->>Client: بررسی فیلد تله ربات (Honeypot Check == "")
 Client->>SupaAPI: POST /rpc/submit_public_response(payload)
 
 activate Postgres
 SupaAPI->>Postgres: اجرای تابع SECURITY DEFINER
 Postgres->>Postgres: بررسی باز بودن فرم و عدم انقضا
 Postgres->>Postgres: INSERT INTO responses (form_id, device, duration...)
 Postgres->>Postgres: INSERT INTO answers (response_id, question_id, value...)
 Postgres->>Postgres: افزایش شمارنده پاسخ‌های ماهانه در profiles
 Postgres->>Postgres: صدور رویداد PostgreSQL WAL CDC
 Postgres-->>SupaAPI: وضعیت موفقیت { success: true, response_id: ... }
 deactivate Postgres

 SupaAPI-->>Client: تاییدیه ثبت پاسخ (200 OK)
 Client->>Storage: پاک کردن پیش‌نویس فرم (Draft Cleared)
 Client->>User: پخش انیمیشن کانفتی و نمایش صفحه تشکر (Exit Screen)

 %% Realtime Push
 Postgres-)Realtime: رویداد تغییرات جدول (New Row in responses)
 activate Realtime
 Realtime-)Admin: ارسال پیام وب‌سوکت (Push New Response Alert)
 deactivate Realtime
 Admin->>Admin: نمایش اعلان توست زنده + افزایش شمارنده ثبت‌ها در داشبورد
تراکنش اتمیک در تابع ذخیره‌شده
  • تضمین عدم ورود ناقص داده: تابع submit_public_response با تراکنش داخلی، از ثبت ناقص فرم جلوگیری می‌کند؛ در صورت بروز هرگونه خطا تمام عملیات Rollback می‌شود.
  • امتیاز امنیتی Security Definer: به کلاینت پاسخ‌دهنده اجازه می‌دهد بدون دسترسی مستقیم نوشتن در جداول، پاسخ‌های خود را به صورت کنترل‌شده و ایزوله ثبت نماید.
  • محاسبه مدت زمان واقعی: فاصله زمانی بین گام ۱ (لود صفحه) و گام ۱۰ (ثبت نهایی) با دقت میلی‌ثانیه اندازه‌گیری و در فیلد duration_seconds ذخیره می‌شود.
مسیر لبه و کش موضعی کلاینت
  • پایداری وضعیت (Persistence): هر بار تغییر پاسخ بلافاصله در LocalStorage کش می‌شود تا اگر صفحه به طور تصادفی ریفرش شد، کاربر از همان نقطه ادامه دهد.
  • ارزیابی شروط در کلاینت بدون تاخیر سرور: گام ۸ به صورت کاملاً لوکال و بدون نیاز به ارسال درخواست شبکه اجرا می‌شود تا تجربه پاسخ‌دهی روان بماند.
  • پاکسازی کش: بلافاصله پس از دریافت پاسخ 200 از سرور، کلید مربوط به پیش‌نویس فرم به طور خودکار از حافظه مرورگر کاربر حذف می‌شود.
انتشار وب‌سوکت فینیکس (Realtime Push)
  • مکانیسم CDC مبتنی بر WAL: تغییرات سطح دیتابیس توسط هسته سرور ریل‌تایم مانیتور شده و با کمترین سربار پردازشی به کانال مشترکین ارسال می‌شود.
  • شنود در پس‌زمینه پنل ادمین: هوک useRealtimeSubscription سطر جدید را دریافت و استیت React را بدون نیاز به رفرش صفحه بروز می‌کند.
  • همگام‌سازی اعلان صوتی: مدیر بلافاصله صدای بیپ آرام و توست حاوی مشخصات پاسخ جدید را مشاهده می‌کند.
